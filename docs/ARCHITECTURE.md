# Архітектура

## Три шари

```
┌─────────────────────────────────────────────────────────────┐
│ ui/  React-компоненти, CSS Modules                          │
│   StartScreen · GameScreen (+ Dice, FarmPanel, MapScene…)    │
│   overlays/  ResultModal · RulesSheet · TradeSheet · WinModal│
│              SettingsSheet                                   │
└───────────────▲──────────────────────────────┬──────────────┘
                │ стан + дії (GameApi)        │ рендер спрайтів
┌───────────────┴──────────────────────────────▼──────────────┐
│ app/useGame.ts   React-стан, тайминги, звук, автозбереження │
└───────────────▲──────────────────────────────┬──────────────┘
                │ GameState / RollOutcome      │ read/write
┌───────────────┴──────────────────────────────▼──────────────┐
│ game/   ЯДРО: engine.ts (чисті функції) · config.ts · types  │
│         settings.ts (правила + звук + тема) · storage.ts     │
│         sound.ts · haptics.ts                                │
└─────────────────────────────────────────────────────────────┘
```

Ключова властивість: `resolveRoll(state, faces)` — **чиста** функція. Вона не мутує
вхідний стан (клонує через `structuredClone`), не торкається DOM і не використовує
таймерів. Тому правила покриті тестами без браузера, а анімації можна міняти, не
ризикуючи логікою.

## Потік одного ходу

```
натиск «🎲 Кинути кубики»
  └─ useGame.roll()
       ├─ sound.roll() + haptic('light')
       ├─ rollDice()            → випадкові грані (DIE_ONE, DIE_TWO)
       ├─ ~880 мс анімація      (Dice показує випадкові грані)
       ├─ resolveRoll(state, faces)
       │    ├─ хижаки: лисиця/ведмідь → пес захисник або втрата тварин
       │    ├─ розмноження: floor((у дворі + грані) / 2) тварин зі стада
       │    └─ новий GameState + events + deltas + tone + won
       ├─ setState / flashDeltas (бейджі +N/−N живуть 1.8 с)
       └─ +520 мс → ResultModal із поясненням кожного рядка
```

Передача ходу (`endTurn`) — окрема чиста функція: змінює гравця, скидає прапорці ходу,
піднімає номер кола, пише в лог, показує `HandoffOverlay` (сам зникає через 2.4 с).

## Обмін

`availableTrades(state)` повертає всі досяжні кроки драбини в обидва боки.
Скільки їх можна зробити за хід — вирішує `TRADES_PER_TURN` у `config.ts`
(`null` = без обмежень), а `canTrade()` / `tradesLeft()` дають це UI.
Панель обміну групує варіанти на «вгору» (кілька молодших → старша), «вниз»
(старша → кілька молодших) і «собаки», показує спрайти та кількість до/після
обміну, і **не закривається** після дії — можна одразу зробити наступний.

## Стан і збереження

`GameState` — серіалізовний об'єкт (жодних класів, дат і посилань). Завдяки цьому:

* автозбереження — це один `JSON.stringify` у ефекті `useEffect([state])`;
* завершена партія **не** зберігається (`saveGame` видаляє ключ, якщо `state.over`);
* `storage.ts` містить перевірку формату й константу `SAVE_SCHEMA` — при зміні структури
  піднімайте версію, і старі збереження просто ігноруються;
* у приватному режимі (коли `localStorage` кидає помилку) гра працює без збереження.

Окремо **два сховища**:

| Ключ | Що лежить | Хто читає |
| --- | --- | --- |
| `lux-ferma:save` | `GameState` разом із `state.rules` | `storage.ts` |
| `lux-ferma:settings` | `AppSettings` (правила за замовчуванням + звук + тема) | `settings.ts` |

`state.rules` — це **знімок** правил на момент партії: відкрив стару гру через тиждень —
вона грається так, як її почали, навіть якщо типові налаштування вже інші. Зміна
налаштувань у грі оновлює і `AppSettings`, і `state.rules` — тому «вимкнути хижаків»
посеред партії працює одразу.

## Спрайти й фолбеки

`src/assets/manifest.ts` збирає URL усіх спрайтів від `import.meta.env.BASE_URL` — тому
один білд працює і в підкаталозі на вебі, і в Capacitor (де корінь інший).
`useAssets()` (через `useSyncExternalStore`) тягне зображення наперед і віддає карту
`url → чи готове`. Компонент `Sprite` показує емодзі, поки картинки немає, — гра
лишається читабельною на повільному з'єднанні й не «стрибає» після завантаження.

## Карта ферми

`map.webp` (1664×928) уже містить намальовані паркани, ставок, дерева, соняшники, річку
й місток. Тому:

* `ZONES` у `config.ts` — прямокутники **у відсотках**, виміряні по арті (сітка 10%
  накладалася скриптом), кожен накриває намальований загін;
* `DECOR` містить лише те, чого на арті немає — обійстя фермера й млин;
* усередині зони окремо задані прямокутники для будівлі та для тварин.

Зони — звичайні кнопки (`<button>`), тому працюють із клавіатури; клік показує довідку
в «Стрічці подій».

## Адаптив

| Ширина | Що показуємо |
| --- | --- |
| < 420 px | 3 колонки дворів, без назв (лише спрайт + лічильник), звук/правила в топбарі |
| 420–999 px | 2 колонки дворів, повні підписи |
| ≥ 1000 px | HUD ліворуч (кубики, рахунок, стрічка), карта ферми праворуч |

Панель дій завжди закріплена внизу: `.shell` має висоту `100dvh` і `overflow: hidden`,
скролиться тільки середина. Це гарантує, що «Кинути кубики» видно на будь-якому телефоні.

## Звук і тактильність

`sound.ts` синтезує сигнали через Web Audio (жодного аудіофайлу в бандлі): кидок,
прибуття тварин, напад, обмін, перемога, клік. Кожен сигнал має ідентифікатор
`SoundEffect`, тож у «Налаштуваннях» його можна вимкнути окремо; вмикання одразу
програє сигнал — чути, що саме вмикаєш. Гучність (0–1) множиться на рівень
кожного сигналу, тож «тихо» не означає «вимкнено».

`haptics.ts` використовує Capacitor Haptics на телефоні й `navigator.vibrate` у браузері;
перемикач — `haptics.enabled` з налаштувань. Тему задає `applyRuntime()` на
`document.documentElement.dataset.theme` (`system` = атрибут прибрано), тому CSS
перемикається без перерендеру компонентів.

## Розширення

**Новий вид тварини.** Додати ключ у `Species`/`HerdKey` (`types.ts`), запис у `ANIMALS`,
спрайт у `public/assets/animals`, рядок у `BUILDINGS` і `FACE_SPRITE`, координати в
`ZONES` та `TRADE_LADDER` за потреби → `npm run test`.

**Зміна балансу.** Тільки `BALANCE` у `config.ts`. Тести перевіряють правила, а не
конкретні цифри стада, тому пресети можна міняти вільно.

**Новий екран.** Файл у `src/ui/screens/`, стан — у `useGame` або локально. Оверлеї —
через готовий `Overlay` (центр/шит) + спільні стилі `Overlays.module.css`.
