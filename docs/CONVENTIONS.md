# Конвенції репозиторію

Коротко: **правила гри не знають про React, UI не знає про правила.**

## Межі шарів

| Папка | Можна | Не можна |
| --- | --- | --- |
| `src/game/` | чистий TS, `structuredClone`, `Math.random` через параметр | імпортувати React, DOM, `window`, `localStorage` (крім `storage.ts`) |
| `src/app/` | React-хуки, тайминги, звук, localStorage | описувати правила гри (тільки викликати `engine.ts`) |
| `src/ui/` | рендер, анімації, локальні стани відкритих модалок | рахувати ігрові числа (пари, розмноження, обмін) |
| `src/assets/` | URL спрайтів, попереднє завантаження | розміри/розкладку елементів |

Будь-яка нова логіка правил іде в `engine.ts` **і супроводжується тестом** у
`engine.test.ts`. Якщо функцію складно протестувати — вона розташована не в тому шарі.

## Правила гри — через config, налаштування — через settings

Ніяких «магічних» чисел у компонентах: грані кубиків, ліміти, драбина обміну, координати
карти — все в `src/game/config.ts`. Дві різні цифри стартового стада з прототипів
збережено як `BALANCE.classic` / `BALANCE.compact`; за замовчуванням `classic`.

Якщо параметр має бути доступний гравцеві — він іде у `GameRules`
(`src/game/settings.ts`), а не читається рушієм прямо з константи:

1. тип правила — у `GameRules` + `DEFAULT_SETTINGS`;
2. варіанти для UI — у `config.ts` (`TRADE_LIMIT_OPTIONS`, `PREDATOR_MODES`,
   `DICE_PRESETS`) з `label` + `hint`;
3. рушій бере значення **зі стану**: `state.rules.tradesPerTurn`,
   `state.rules.predatorMode`, `state.rules.dicePreset` — щоб збережена партія
   гралась за своїми правилами;
4. `sanitizeSettings()` мусить знати нове поле (інакше воно не переживе перезапуск);
5. тест на нову поведінку — у `src/game/settings.test.ts`.

Глобальні константи (`TRADES_PER_TURN` тощо) для таких параметрів не заводимо:
два джерела правди для одного правила — це баг, який чекає свого часу.

## Стилі

* Спільні примітиви (`btn`, `btn--green`, `card`, `sheet`, `overlay`, `icon-btn`) — у
  `src/styles/global.css`, вони навмисно глобальні.
* Усе специфічне для компонента — у його `*.module.css` (scoped класи).
* Кольори, радіуси, шрифти — тільки через змінні з `src/styles/tokens.css`. Новий колір
  додавайте токеном, а не хардкодом.
* Mobile-first: базові стилі — телефон, `@media (min-width: 420px)` / `(min-width: 1000px)`
  — ускладнення. Мінімальна ціль дотику — 48px (`--tap`).

## Асети — тільки через скрипт

`public/assets/**` і `public/icons/**` генеруються `npm run assets`. Не редагуйте ці файли
руками: оновіть сирці PNG і перегенеруйте. Новий спрайт = новий рядок у `config.ts`
(`ANIMALS` / `BUILDINGS` / `DECOR`); реєстр URL у `src/assets/manifest.ts` підтягне його сам.
Фолбек на емодзі обов'язковий (компонент `Sprite`).

## Розкладка карти — через дев-редактор, а не наосліп

`ZONES` і `DECOR` — це відсотки від площі карти. Щоб їх правити, не вгадуючи числа,
відкривайте `npm run dev` → `http://localhost:5173/?editor=1` (десктопна ширина):
тягнете рамки мишею, тиснете «Копіювати JSON» і вставляєте результат у `config.ts`.
Код редактора (`src/ui/dev/`) підключено динамічно тільки в DEV — у прод-бандл він не
потрапляє, тому в ньому можна тримати будь-які діагностичні інструменти.

## Екран мусить влазити

Панель дій завжди видима: `.shell` має фіксовану висоту `100dvh`, скролиться лише
середина (сітка дворів / HUD-колонка). Перед завершенням верстки перевірте:

```bash
npm run build
npx vite preview --port 5199 &
node scripts/measure-layout.mjs http://localhost:5199 375 667   # «зайве 0px» = ок
node scripts/screenshots.mjs http://localhost:5199 /tmp/shots   # візуальний контроль
```

## Перед комітом

```bash
npm run typecheck && npm run test && npm run lint && npm run build
```

Критерії: 0 помилок типів, усі тести зелені, 0 попереджень oxlint, успішний білд.

## Натив

`src/app/native.ts` — єдине місце, де згадується Capacitor. Плагіни підвантажуються
динамічно (`await import(...)`), щоб не тягнути нативний код у веб-бандл, і всі виклики
обгорнуті в `try/catch` — на вебі це no-op. Не додавайте нативних залежностей без
необхідності: кожен плагін — ще один шар для тестування на двох платформах.

## Мова

Коментарі, UI-тексти й документація — українською. Код (ідентифікатори, типи) —
англійською. Коміт-повідомлення — англійською, у стилі conventional commits.
