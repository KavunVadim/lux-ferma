# 🚜 Люкс Ферма — помічник для гри

[![Грати онлайн](https://img.shields.io/badge/▶_грати-lux--ferma.vercel.app-000000?logo=vercel&logoColor=white)](https://lux-ferma.vercel.app/)
[![CI](https://img.shields.io/badge/тести-55_зелених-4b7f52)](https://github.com/KavunVadim/lux-ferma)

**🕹 Жива гра: <https://lux-ferma.vercel.app/>** — відкривається у браузері на телефоні
чи ПК і встановлюється як застосунок (Android: Chrome → «Встановити»; iOS: Safari →
«На екран Домівки»). Кожен `git push` у `main` автоматично оновлює цю версію.

Цифровий помічник для настільної гри «Люкс Ферма»: кидок кубиків, розмноження тварин,
напади хижаків, собаки-охоронці, обмін і визначення переможця. Один пристрій на всю
компанію (2–4 гравці передають його по колу).

**Один код — два світи:** той самий білд відкривається як вебзастосунок (PWA, працює
офлайн) і загортається в нативні застосунки для iOS/Android через Capacitor.

## Асети

Сирці (великі PNG) не лежать у репозиторії — у ньому лише результат:

```bash
npm run assets                                  # джерело за замовчуванням
npm run assets -- --src /шлях/до/assets         # або вказати папку
```

Скрипт робить WebP (максимальний бік 512–900 px, q86–88) і генерує іконки застосунку
зі спрайта качки. Результат — **21 МБ → 1.8 МБ (92% економії)**, ~200 кБ із них — карта.
Файли в `public/assets` комітяться: `npm install && npm run build` працює без сирців.

## Шрифти

`npm run fonts` тягне з Google Fonts лише потрібні subsets (latin, cyrillic,
cyrillic-ext) у `src/styles/fonts/` і генерує `src/styles/fonts.css`. У продакшн-білді
Vite хешує файли сам. **Увага:** «Baloo 2» з вихідного прототипу не має кирилиці —
заголовки замінено на «M PLUS Rounded 1c» (той самий округлений характер + повна
українська), текст — «Nunito».

## Вебзастосунок

`npm run build` → папка `dist/` (статика + service worker). Її можна покласти на будь-який
хостинг: гра працює офлайн (крім найпершого завантаження), встановлюється на телефон
як PWA («Додати на початковий екран»).

## Збірка під телефони (Capacitor)

Потрібні нативні тулчейни (на цій машині їх ще немає):

* **iOS:** macOS + Xcode + CocoaPods (`sudo gem install cocoapods`)
* **Android:** Android Studio + JDK 21 + Android SDK

```bash
npm run build
npx cap add ios        # один раз
npx cap add android    # один раз

npm run cap:ios        # білд + sync + відкрити Xcode
npm run cap:android    # білд + sync + відкрити Android Studio
```

Нативні проєкти (`ios/`, `android/`) створюються один раз і комітяться; `dist/` лишається
артефактом. Після `cap sync` застосунок виглядає однаково на всіх платформах.

## Налаштування гри (екран ⚙️)

Гравці керують параметрами самі — без правок коду. Екран відкривається з
стартового меню («⚙️ Налаштування гри») або з верхньої панелі під час партії.

| Група | Що змінює |
| --- | --- |
| 🔁 Обміни за хід | без обмежень / 1 / 2 / 3 — `GameRules.tradesPerTurn` |
| 🦊🐻 Хижаки | як у грі (забирає всіх) / мʼякі (половина) / вимкнені |
| 🎲 Кубики | класичні / спокійніші (без хижаків на гранях) |
| 🧺 Стартове стадо | `BALANCE.classic` / `BALANCE.compact` (діє з наступної партії) |
| 🔊 Звук | увімк/вимк, гучність 0–100%, окремі перемикачі на 6 сигналів |
| 📳 Вібрація | тактильний відгук на телефоні |
| 🎨 Тема | як у системі / світла / темна |
| 🎬 Анімація кидка | чи показувати хижаків, поки кубик крутиться |

Технічна механіка:

* `src/game/settings.ts` — тип `AppSettings`, `sanitizeSettings()` (будь-яке сміття
  з localStorage стає валідними налаштуваннями), `applyRuntime()` (звук + вібрація + тема);
* **правила копіюються у партію**: `GameState.rules` (тип `GameRules`) — збережена
  гра завжди грається за тими правилами, з якими її почали;
* зміна під час партії застосовується одразу (обміни, хижаки, кубики, анімація),
  бо UI оновлює і налаштування, і `state.rules` одночасно; стартове стадо — ні,
  воно роздається лише на старті;
* `SAVE_SCHEMA` = 3 (додано `rules`).

## ПК: поле на весь екран

На екранах ≥1000px гра виглядає як настільна гра, а не як форма:

* **одна карта ферми на весь екран** — спільна для всіх гравців, показує те, що
  зараз у дворі поточного (при передачі ходу карта «перемикається»);
* **інтерфейс живе у вільних смугах карти**: верхня (над затоками) — чип ходу й
  дрібні кнопки, нижня (під загонами, де лише трава й соняшники) — вивіска
  «Люкс Ферма», чипси гравців і лоток дій. Загони з качками, свинями та кіньми
  лишаються повністю відкритими;
* **кубики — не постійний блок, а вікно**: натиснув «Кинути кубики» — з'явилось
  плаваюче вікно (`Overlay variant="float"`, без затемнення), у ньому летять
  кубики, а потім у тому ж вікні показується результат із картками. Пауза перед
  вікном різна за тоном (`RAID_DELAY`/`BORN_DELAY`) — щоб набіг хижака чи
  прибуття тварин було видно на карті, а не за модалкою;
* **історія ходів прихована** за кнопкою 📜 (панель знизу) — основний екран не
  захаращений;
* полотно карти тримає пропорції арта й масштабується як `cover`
  (`width: max(100%, calc(100vh * 1.7931))`), тому координати загонів у
  відсотках завжди збігаються з намальованими.

Мобільна версія (до 1000px) не змінюється: одна колонка, кубики зверху, сітка
дворів. Вікно результату на телефоні — звичайна панель знизу.

## Продуктивність (правила, які не можна ламати)

ПК гальмував через дві речі, обидві вже виправлені — і заміряні:

| Було | Стало | Чому це важливо |
| --- | --- | --- |
| `filter: drop-shadow` на **рухомих** спрайтах | статична тінь під ногами (`.slot::before`) | браузер перемальовував фільтр щокадру на кожній тварині |
| кадри ходи анімували `left` | `transform: translate3d` | `left` = перерахунок розкладки щокадру |

Замір на прод-збірці (`npm run preview`), однакові умови, 6 ходів з повним двором:

```
до:  найдовший кадр 223 мс · довгих задач 1 (73 мс)
після: найдовший кадр  80 мс · довгих задач 0
```

**Правила для нових анімацій** (щоб не повернути проблему):

1. Рухомі елементи — тільки `transform` / `opacity`. Ніколи `left`, `top`, `width`,
   `background-position`, `filter`.
2. Тінь під твариною — статичний `::before` з радіальним градієнтом, не `drop-shadow`.
3. `will-change: transform` лише на тих вузлах, які справді рухаються безкінечно.
4. `contain: layout style` на комірці загону; `contain: layout paint` **не** ставити —
   обрізає пил і кроки тварин.

**Витоки пам'яті.** Таймери прибирають себе самі (`later()` у `useGame`, `scheduled`
у `sound.ts`), журнал подій обмежений `MAX_LOG`, підписки відписуються при розмонтуванні.
Перевірити знову: `npm run check:perf` (грає ходи, тисне GC через CDP і показує FPS,
найдовший кадр, довгі задачі, вузли DOM і heap).

## Що змінювати для правок правил

Усе живе в `src/game/config.ts`:

* `BALANCE.classic` / `BALANCE.compact` — стартовий запас спільного стада
  (у прототипах було дві різні цифри; за замовчуванням — `classic`).
* `DIE_ONE` / `DIE_TWO` — грані кубиків (по 12); `DICE_PRESETS` — набори для
  налаштувань (`classic`, `calm`).
* `TRADE_LADDER` — таблиця обміну; `SPECIES_TIER` — порядок старшинства видів
  (за ним обміни діляться на «вгору» й «вниз» у панелі обміну).
* `TRADE_LIMIT_OPTIONS`, `PREDATOR_MODES` — варіанти, які бачить гравець у
  «Налаштуваннях»; типовий ліміт обмінів — `DEFAULT_SETTINGS.tradesPerTurn`
  (`null` = без обмежень).
* `ANIMALS`, `PREDATORS` — назви, емодзі, спрайти, хто кого краде/захищає.
* `ZONES` / `DECOR` — розкладка карти у відсотках (правте в редакторі, див. нижче).

Після зміни правил: `npm run test` (тести в `src/game/engine.test.ts`).

## Хода тварин (спрайт-листи)

Статичний спрайт із CSS-погойдуванням — це мінімум. Щоб тварини справді
крокували, гра вміє показувати **спрайт-лист ходи** (горизонтальна стрічка
квадратних кадрів), а `npm run atlas` збирає такі листи:

```bash
npm run atlas          # демо-кадри зі спрайтів (щоб побачити конвеєр)
npm run atlas -- --clean   # лише те, що лежить в assets-src/walk/<вид>/
```

* джерело справжніх кадрів: `assets-src/walk/duck/001.png … 008.png`
  (нарізати з AI-відео: PNG тварини → Runway/Kling/Luma «walking loop» →
  `ffmpeg -i walk.mp4 frames/%03d.png`);
* скрипт вписує кожен кадр у квадратну комірку 176×176, зшиває стрічку в
  `public/assets/walk/<вид>.webp` і пише маніфест `src/assets/walk.ts`;
* у грі `WalkToken` показує стрічку через `steps(frames)`, а якщо листа немає —
  падає на статичний спрайт (тобто наповнювати можна по одному виду);
* темп кроку й фаза — випадкові на кожну тварину (`--walk-dur`, `--delay`),
  тому загін не крокує в унісон;
* перевірка: `node scripts/measure-hud.mjs` друкує, скільки спрайтів ходи на
  полі, скільки кадрів у стрічці та чи зсувається кадр (він має зсуватись рівно
  на одну комірку за крок).

Бриф на нову арту карти — `docs/ART-BRIEF.md` (готовий промпт + технічні вимоги).

## Аудит кубиків

`src/game/dice.test.ts` перевіряє, що розподіл граней справді такий, як задумано
(1 ведмідь з 12 граней 1-го кубика, 1 лисиця з 12 граней 2-го), і друкує звіт із
частотами. Замір на 200 000 кидків через справжній рушій:

```bash
npx vitest run src/game/dice.test.ts --reporter=verbose --silent=false
```

```
  ведмідь на 1-му кубику : 8.29%   (задум 8.33%, 1 грань із 12)
  лисиця на 2-му кубику  : 8.34%   (задум 8.33%, 1 грань із 12)
  хоч один хижак за хід  : 15.96%  (задум 15.97% ≈ 1 з 6)
  обидва хижаки за хід   : 0.68%   (задум 0.69%)
```

Тобто напад — приблизно **раз на 6 ходів кожного гравця**. Якщо це занадто часто
для вашої компанії — не треба чіпати код: у «Налаштуваннях» є режим хижаків
(`мʼякі` = забирає половину) і набір кубиків `спокійніші` (хижаків на гранях немає).
Для постійної зміни правте `DIE_ONE` / `DIE_TWO` або `DICE_PRESETS` у `config.ts`.

## Редактор карти (розкладка спрайтів мишкою)

Координати загонів, будівель, тварин і декору задані у відсотках у
`src/game/config.ts` (`ZONES`, `DECOR`). Щоб не підбирати числа наосліп, є дев-редактор:

```bash
npm run dev
# відкрити http://localhost:5173/?editor=1  (вікно ≥1000px, потрібен десктопний вигляд)
```

**Одне посилання — і редактор на екрані.** У dev-режимі `?editor=1` сам створює
партію (2 гравці) і не показує екран передачі ходу, тож нічого натискати не треба:
маркери всіх об'єктів видно одразу, у панелі знизу — готовий код `ZONES`/`DECOR`
і кнопка **«Копіювати JSON»**.

У прод-бандл редактор не потрапляє взагалі (динамічний імпорт під `import.meta.env.DEV`):
перевірка `grep -rl "Редактор карти" dist/assets` дає 0 файлів.

* **жовта рамка** — загін, **червона** — будівля всередині загону, **синя** — місце спрайтів
  тварин, **фіолетова** — декор;
* тягнеш рамку за тіло — рухаєш, за правий нижній квадратик — розмір (крок 0.5%);
* під картою — готовий фрагмент `config.ts`: тиснеш **Копіювати JSON**, вставляєш у файл
  замість старих `ZONES`/`DECOR` і перезавантажуєш сторінку (значення з файлу стануть базою);
* **Сітка** — лінії кожні 10% (як на самій арті), **Скинути** — повернути значення з config.

Редактор підключається динамічно лише в режимі розробки, тож у продакшн-бандл не потрапляє
(перевіряється `grep` по `dist/assets/*.js`). Поки редактор відкритий, оверлеї гри (передача
ходу, результат кидка) не показуються — вони перехоплюють кліки по рамках.

Сам перетяг можна перевірити без рук:

```bash
node scripts/check-editor-drag.mjs      # справжній drag мишею через CDP + перевірки
```

## Перевірка UI без рук

```bash
npm run build
npx vite preview --port 5199 &
node scripts/screenshots.mjs http://localhost:5199 /tmp/shots   # 9 станів гри
node scripts/measure-layout.mjs http://localhost:5199 375 667   # чи влазить екран
```

Екран «Налаштування» перевіряється окремо — не лише те, що він малюється, а й те,
що вибір справді змінює гру (з вимкненими хижаками кидок «ведмідь + лисиця» нічого
не забирає):

```bash
npm run dev                                    # в іншому терміналі
npm run check:settings                         # 21 перевірка у справжньому Chrome
```

Скрипт пише знімки (`settings-sheet.png`, `settings-dark.png`, `settings-off-roll.png`)
у `/tmp` — зручно глянути оком після змін у верстці.
